# Changelog

All notable framework changes are documented here. This project follows
Semantic Versioning for the primary AUD framework; specialist plugins may keep
independent versions.

## [0.2.0] - 2026-09-04

### Added

- Versioned shared contracts, validation, fixtures, stable IDs, lifecycle
  protocol, immutable run layout, and persistent-ledger merge behavior.
- Structured adapters for content, place, flow, visual, and functional audits.
- The four-mode `aud` orchestrator with deterministic selection, dependency
  waves, reusable revision-pinned evidence, degraded-mode reporting, and atomic
  persistence.
- Cross-audit synthesis, contradiction preservation, root-cause qualification,
  remediation priority and dependency planning, evidence-backed verification,
  regression findings, and legal lifecycle transitions.
- A versioned 22-case calibration corpus, reliability metrics, drift reports,
  reviewed baselines, and hard/warning quality gates.
- Selective `architecture-maintainability-audit` coverage for dependency
  direction, ownership, coupling, change amplification, and structural test
  seams.

### Changed

- Broad and ambiguous requests now route through `aud`; direct specialist
  commands remain available for narrow explicit requests.
- Audit and verification plans can contain six specialist decisions while
  remaining compatible with immutable five-specialist Phase 3–6 artifacts.
- The primary AUD plugin now follows the public framework release version
  `0.2.0`; previous `6.0.0` and `7.0.0` values were phase markers.

### Compatibility

- Node.js 22–24 on Ubuntu and Windows.
- Existing v1 shared schemas remain supported. Phase 4 emits remediation plan
  v2 and Phase 5 emits verification result v2 while their documented legacy v1
  inputs remain accepted.
- `audit` remains a temporary alias for `functional-audit`.

### Known limitations

- Security/privacy has no specialist until threat-model and data-classification
  foundations and calibration cases exist.
- Architecture analysis is portable and evidence-driven but does not include
  language-specific dependency graph extractors.
- The calibration corpus is synthetic and needs reviewed real-world cases over
  time.
