# AUD framework v0.2.0 release notes

AUD framework 0.2.0 is the Phase 0–7 baseline. It turns the existing audit
specialists into one contract-driven, report-only framework without removing
their standalone commands.

## Highlights

- One `aud` entry point supports diagnose, redesign, verify, and specialist
  modes with deterministic selection and recorded skip/defer reasons.
- Content-dependent work runs in order; place and flow become parallel-ready
  only after a compatible content contract or an explicit degraded decision.
- Specialists share revision-pinned evidence and emit schema-valid findings
  with stable IDs, native metrics, consequence severity, separate confidence,
  evidence references, and verification handoffs.
- Synthesis preserves specialist facts while grouping duplicates, exposing
  contradictions, qualifying root-cause inference, and producing ordered
  remediation plans.
- Verification compares baseline and candidate evidence, records regressions,
  and changes lifecycle state only through legal evidence-backed transitions.
- The Phase 6 reliability harness gates the framework against 22 deterministic
  cases. Phase 7 selectively adds architecture/maintainability without expanding
  generic product audits.

- Clean install: `npm ci`
- Complete suite: 19 test files
- Schemas: 27 registered schemas and fixture sets
- Marketplace manifests: 8 plugins
- Full calibration: 22 cases, pass
- Quality gate: pass, compatible baseline, zero hard failures and warnings
- Finding precision/recall: 1.0/1.0; false-positive and false-negative rates: 0
- Schema validity, provenance completeness, and deterministic rerun agreement:
  1.0
- Mutation violations, fabricated results, critical false negatives, and
  verification without evidence: 0

## Upgrade and compatibility

The release supports Node.js 22–24 on Ubuntu and Windows. No v1 shared schema is
removed. Consumers of audit or verification plans must look up decisions by
specialist name and allow either five legacy or six current entries. Continue
to use `functional-audit`; `audit` remains only as a temporary alias.

See [compatibility.md](../compatibility.md) and
[phase-2-migration.md](../phase-2-migration.md) before updating automation.

## Remaining limitations

- Security/privacy coverage remains deferred pending explicit threat-model,
  trust-boundary, data-classification, jurisdiction, and calibration inputs.
- Architecture review does not yet bundle language-specific graph extractors.
- Performance remains within functional audit until measured misses justify a
  separate specialist.
- Evidence integrity remains shared infrastructure, and decision quality remains
  synthesis-owned, rather than becoming redundant specialist modules.
- The calibration corpus is synthetic; reviewed real-world cases are the next
  reliability investment.

This release does not deploy or modify audited applications.
